# Domain Docs

How engineering skills consume this repo's domain documentation.

## Before exploring, read these

- **`CONTEXT.md`** at the repo root.
- **`docs/adr/`**: read ADRs relevant to the area being worked on.

## Use the glossary's vocabulary

When naming a domain concept (in ticket titles, refactors, tests, or code), use the term defined in `CONTEXT.md`. Do not introduce synonyms that the glossary explicitly avoids.

## Flag ADR conflicts

If an output contradicts an existing ADR, surface it explicitly rather than silently overriding it.
